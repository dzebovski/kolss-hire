# Перевірка реалізації KOLSS Hire

Дата: 07.10.2026. Реалізація локальна; push і deployment не виконувалися.

## Результат

Готові три мовні лендинги, подяка, privacy-shell, SEO/OG, доступна форма, перевірка CV, Slack API, BotID, consent і Meta Pixel/CAPI. Актуальні Main/Mobile і стани прочитані з Claude canvas; українські редакторські правки перенесені у spec.

Прийняте рішення власника: PDF/DOC/DOCX до 4 MB (4 000 000 байтів). Для більших CV — посилання. Загальний запит обмежений 4 400 000 байтів, нижче ліміту Vercel 4,5 MB.

## Перевірено

- ESLint і TypeScript — без помилок.
- Vitest: 7 тестів локалі та 6 тестів прикладної логіки; перевірено обов’язкові контакти, CV файл/URL, 4 MB межу, довжину коментаря, сигнатури, SHA-256, нормалізацію й Slack escaping. Файли запущені окремо, без coverage.
- Production build — успішний: усі дев’ять мовних сторінок prerendered. Node.js використовується за замовчуванням, явний runtime export несумісний з Cache Components у Next 16.4.
- Production HR-guard очікувано відхиляє всі три словники; preview/local build працює.
- Audit production dependencies — 0 відомих вразливостей на момент перевірки.
- HTTP: кореневий 307 за Accept-Language зі збереженням query; security headers; невідома локаль 404; український OG повертає PNG 200.
- Браузер: PL/UK/EN, подяка і privacy; hero CTA скролить і фокусує перше поле; порожня форма показує помилки з фокусом та aria-invalid; відправка без Slack env показує помилку сервера й зберігає контакти та вибраний файл.
- Mobile sticky CTA видима після hero, прихована біля форми і при відкритому банері; відхилення cookies ховає банер, налаштування відкривають його знову. При порожньому Pixel ID DOM не містить Facebook script.
- Скриншоти production UK на viewport 390 і 1440 px у `docs/screenshots/`; viewport captures мають повну задану ширину, full-page captures виключають scrollbar. Горизонтального overflow на 390 px немає.

## Межі та ризики

Slack є єдиним сховищем: недоступність API означає незбережену заявку і повторну відправку кандидатом. Якщо Slack прийняв заявку, але відповідь загубилася, повтор може створити дублікат. Retention і доступи HR-каналу налаштовує власник. BotID fail closed; його production-поведінку треба перевірити на Vercel. Сигнатура DOCX перевіряє ZIP magic, а не структуру Office-документа.

Початкові зміни AGENTS.md, PROJECT.md, TASKS.md, docs/01–03 та public/brand були незакомічені до роботи. Їх не включено до комітів реалізації; вони залишаються у робочій директорії. Оновлення цих документів описують прийняті рішення. Перед push власнику потрібно також включити необхідні бренд-активи.

### Фінальні перевірки

- `npx tsc --noEmit`, `npm run lint`, `npm test` — успіх, 17 тестів. Чотири нові тести перевіряють 10 однакових id, однакову кількість cookie-рядків, відсутність HR-маркерів і заборону запису fbclid без granted consent; jsdom не додано.
- `VERCEL_ENV=production npm run build` — успіх, content check пройшов.
- Privacy: 10 існуючих анкорів; native browser click на #cookies розміщує заголовок на 24px від верхнього краю; sticky-зміст на desktop, 5 рядків cookie-таблиці і mobile-картки. Title/description/canonical/hreflang перевірені в DOM, privacy для трьох мов є в sitemap.
- Подяка використовує той самий хедер/футер. Хедер на desktop займає 1120px внутрішнього контейнера, не стискається навколо логотипа.
- Логотип має локалізовану aria-label, переходить у поточну мовну вакансію в тій самій вкладці, зберігає UTM/fbclid; на лендингу повертає хедер на top=0. Footer kolss.eu залишився зовнішнім.
- Панель: фокус на заголовку, Space змінює switch, Save/Close/Escape повертають фокус до opener з footer або політики. Білий контур/повзунок і лаймовий активний стан на темному фоні мають контраст понад 3:1. Панель 565px на viewport 390×844, max-height=88svh, внутрішня прокрутка; sticky CTA ховається через bannerOpen.
- Відмова: через тимчасовий локальний діагностичний екран створено синтетичні `_fbp`, `_fbc` і 4 kh sessionStorage ключі; після вимкнення marketing + Save усі видалені, kh_consent=denied. Fresh Reset → банер із трьома кнопками → Reject також лишає sessionStorage порожнім. Діагностичний файл видалено, до комітів не включений.
- При порожньому Pixel ID Facebook script відсутній. **Реальне завантаження Pixel, мережеві запити і одна PageView після Accept не підтверджені:** Pixel ID локально не задано. Це треба перевірити з recruitment dataset на preview, включно з повторним granted після revoke.
- Скриншоти privacy і settings на viewport 390/1440 у docs/screenshots. Захоплення браузера виключає scrollbar/рамку (файли 375/1425px); задані viewport розміри перевірялися окремо.

### Звірка cookie/storage і CAPI

У таблиці наявні всі ключі, які пише сайт: kh_consent (точно 180 днів), kh_fbclid, kh_eid, kh_eid_sent, kh_start_application (sessionStorage). _fbp/_fbc пише Meta Pixel, сайт читає та видаляє їх. Зайвих first-party ключів у таблиці немає; рядок Vercel умовний для production-захисту.

Офіційна документація [BotID](https://vercel.com/docs/botid/get-started) не публікує стабільні cookie names/expiry. У встановленому botid@1.5.11 сервер пересилає cookies із префіксом KP_, але точні назви й строки не підтверджені. [Vercel Firewall](https://vercel.com/docs/vercel-firewall/firewall-concepts) підтверджує годину для browser challenge session, не назву cookie. Тому погоджений generic-рядок не замінено вигаданими назвами; його «сесія або кілька годин» треба уточнити після перевірки production.

CAPI фактично надсилає: event_name, event_time, event_id, action_source, event_source_url; em/ph — SHA-256; fbp/fbc, IP, user-agent — лише якщо доступні. fbc може будуватися з fbclid, навіть коли cookie _fbc відсутня. Ім’я, CV, коментар не надсилаються. Поточний текст узагальнює optional identifiers як cookies і не згадує час/URL/action_source; цю різницю передано власнику, погоджений текст не змінено.

- Підтвердити механізми міжнародної передачі для конкретних юридичних осіб і договорів провайдерів.

Це питання для юридичної перевірки, а не висновок про законність чи незаконність політики. Рішення власника про строк до завершення рекрутації, відсутність майбутньої згоди, IOD і капітал збережено.
